The jump skips two minor versions (0.30 and 0.31), so the upgrade notes of every 0.30.x and 0.31.x release apply (§5). The update guide explicitly says to upgrade to 0.30, follow its notes and confirm everything works, then go to 0.31. Recommendation 2 adds: "Never add 2 or more versions of Decidim to the same deployment to production". Zürich ignored both: it went 0.30.0 → 0.31.x in a single day (commits c68dfa2 → 61754d6) and deployed only 0.31. That worked, but the Zürich issues show no 0.30 intermediate state was ever tested. The stricter alternative is two PROD deployments (0.30.9, then 0.31.8), which means roughly twice the deployment and acceptance-testing effort.

5.2 0.31.0 general notes that affect decidim.swiss

  • Rails 7.2 (§2.1): load_defaults 7.2. Locally, tmp/development_secret.txt is no longer read. Either set SECRET_KEY_BASE or rename the file to tmp/local_secret.txt, otherwise you get ActiveSupport::MessageEncryptor::InvalidMessage (#15405).
  • Rails.application.secrets is removed (§2.2). The plan is to delete config/secrets.yml and config/initializers/decidim.rb and take storage.yml and production.rb from the template. decidim.swiss's secrets.yml already reads from ENV (0.28 template), so most of the work is carrying over the custom keys: translator (deepl.rb), the custom maps logic (decidim.rb:157-175, static_provider/dynamic_provider), omniauth oidc (MEIN_KONTO_*), etherpad and the initiatives settings (decidim.rb:485ff). Zürich kept a trimmed-down decidim.rb containing only the custom config.
  • Shakapacker ~8.3.0 (§2.3). Use ~, not ^, otherwise you get "gem and node package versions do not match". Zürich uses ^8.3.0, which only works because of the lockfile.
  • Deprecated, removed in 0.32 (§2.4): Collaborative Drafts, Sortitions, meeting polls. Check whether any tenant uses them.
  • User groups removed (§3.6). user_groups:remove sends emails to group addresses and members (password reset, change notice). The subtasks can be run individually, so mail can be skipped if needed. One subtask is missing from the release notes table: perform_patches_on_emails sets a random password on patched group accounts and emails it in plain text to every confirmed member (UserGroupMailer.notify_user_group_patched). Known authorship bug: #15448. app/views/decidim/groups/_form.html.erb becomes obsolete.
  • SMS authorizations are deleted (§3.4: revoke:sms forces everyone to re-verify). Each tenant has to be told. The task is generated dynamically in decidim-verifications/lib/tasks/revoke.rake (Decidim.authorization_engines.pluck(:name).each { task authorization … }), so it only exists if the sms workflow is registered when rake loads, which it isn't (load-order bug, decidim#16546). Use Zürich's lib/tasks/sms.rake.
  • Cloud storage public: true (§3.7). Asset URLs change, so S3 hosts must be added to the CSP (default-src, img-src, media-src, connect-src). config/initializers/content_security_policy.rb currently has no S3 host.
  • Cron jobs (§4): add decidim:participants:delete_inactive_participants (default 365 days, sends mail 30 and 7 days before deletion; enabling it is a policy decision per tenant). Metrics are removed, so delete app/jobs/compute_metrics_job.rb (decidim:metrics:all). decidim.swiss uses delayed_job, not Sidekiq, so the sidekiq.yml instructions don't apply.
  • Initiatives signature workflows (§5.8/§5.9). Every initiative type with online signature has to be recreated as Decidim::Initiatives::Signatures.register_workflow(…) in an initializer and then selected in the admin "Signature workflow" field. Affected locally: app/overrides/forms/decidim/initiatives/**/initiative_form_override.rb (signature_type_options) and app/views/decidim/initiatives/initiatives/_form.html.erb. The DB check per tenant (which initiative types use online signature, SMS, or document-number verification) is still open.
  • API (§5.1–5.7): new ENV variables DECIDIM_API_FORCE_API_AUTHENTICATION, DECIDIM_API_JWT_SECRET and DECIDIM_OAUTH_ACCESS_TOKEN_EXPIRES_IN. The OAuth scope public is renamed to profile, which only matters for external OAuth integrations.

5.3 0.30.0 general notes that affect decidim.swiss

  • Social login (§3.4): icon becomes icon_path (media/images/google.svg and so on). In secrets.yml, google already uses icon_path: decidim/brands/google.svg (check the path), and facebook/twitter have no icon set. This goes away along with secrets.yml anyway.
  • HERE static maps (§3.7): decidim.rb:162 still has the old v1.6 URL image.maps.ls.hereapi.com/mia/1.6/mapview. It needs to become https://image.maps.hereapi.com/mia/v3/base/mc/overlay if any tenant uses HERE (configured per tenant through 2_add_map_config_override).
  • Cell cache expiration (§2.4): DECIDIM_CACHE_EXPIRATION_TIME, default 1440 minutes.
  • Ransack 4.2 (§2.5) and routing (§5.2) only matter for custom searchable models or custom routes. Check config/routes.rb and the participatory space context override.
  • GraphQL decidim { version } now returns null (§5.1), unless DECIDIM_API_DISCLOSE_SYSTEM_VERSION=true. This probably explains decidim.swiss#204, where the Decidim Awesome version check showed the wrong version [inference].

5.4 From the blog posts

  • 0.30: ephemeral verification ("one time participation", #13579) can be enabled per component, but only works with a registered ephemeral workflow (zuerich#610, which led to the puzzle/decidim-module-ephemeral_verifications module). Also new: soft delete for spaces and components, admin-managed share tokens (#13221, which replaces the earlier share codes, cf. zuerich#506), voting directly from the proposals list (the source of the zuerich#599 caching bug), and multiple surveys per component.
  • 0.31: the "Appearance" admin page is removed (#14797; CTA button moves into the Hero content block, #14741). Tenant admins have to redo custom CTA and appearance settings. Also: automatic deletion of inactive accounts, the API authentication changes, the new initiative creation wizard (#13952, which affects the local initiative view overrides), and a survey admin UI split into tabs (#14182).

7. Taxonomy migration (as in Zürich)

  • The 0.30 tasks make_plan → import_all_plans generate and import one plan per organization (docs). The update_all_metrics from the 0.30.0 notes no longer exists on 0.31.8; use reset_counters instead (§5.5).
  • In Zürich the default produced: ~Bereiche (all scopes and areas mixed together), ~Kategorien (process categories) and Organisation (process types).
  • Zürich's target structure: split ~Bereiche into Kreise and Themen. There are two ways to do this:
    1. Download and edit the plan between make_plan and import_all_plans, then re-import. This is clean but means longer downtime, and it should be rehearsed against a PROD dump.
    2. Import first, then move entries into the target taxonomy with a DB fix (what Zürich did in #624 during deployment).
  • decidim.swiss is multi-tenant (Luzern, Winterthur, Köniz, deinklima, …), so there is one plan per organization. Each client needs to provide their target structure before the PROD deployment, and Lars said "nur schauen dass die Kategorien nach dem Upgrade richtig eingestellt sind" (decidim.swiss#231).
  • Recommendation from Zürich (#624): build a workflow for using a local PROD DB dump so the migration can be rehearsed.
